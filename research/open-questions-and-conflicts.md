# Open questions and conflicts in official guidance

Research date: 2026-10-19. These items affect what the tool can state as fact. Each one is visible in the app: the affected items are marked **Needs review**, and the caveat text explains the uncertainty. Detailed evidence, with verbatim quotes, is in [notes/](notes/).

| # | Topic | What conflicts or is missing | How the tool handles it | Affected items |
|---|---|---|---|---|
| 1 | Planning / deployment guides | "Plan for unified security operations" and "Deploy for unified security operations" redirect to the ISOC preview page, which targets tenants *without* Sentinel. The transition guide still tells readers to review "all planning guidance". | Uses the transition guide as the primary reference and states the redirect. | PREP-SCOPE-01 |
| 2 | Retirement mechanics | No page explains how redirection works, or what happens on or after 31 March 2027 to workspaces that were never connected. One page still mentions July 2026. | Advises planning to transition well before the date and not relying on an automatic switch. | PREP-SCOPE-03 |
| 3 | Onboarding roles | The roles table lists Security Administrator in all cases; a footnote implies it is needed only with more than one workspace. The persona mapping uses resource-group scope for User Access Administrator, while the onboarding page says subscription scope for Owner. | Treats Security Administrator as required (conservative). | PREP-ACC-01, TRN-08 |
| 4 | "Extra step" without Defender XDR | The transition guide mentions an extra step to trigger the connection without Defender XDR; the onboarding page describes none. | Not presented as a step; flagged as uncertain. | PREP-ACC-01 (caveat), research note 01 |
| 5 | GDAP | Four statements: "not supported" (onboarding, MTO requirements), "in preview" (transition guide), "supported in unified RBAC" (URBAC overview, 2026-10-15), "isn't supported in unified RBAC" (activation page). | Marked unresolved; advises against relying on GDAP for Sentinel data without confirming with Microsoft. | PREP-TOP-05 |
| 6 | CMK | The transition guide says alerts and incidents "will no longer be CMK-encrypted"; the CMK page says operational data (alerts, incidents) uses Microsoft-managed keys anyway. | Both statements shown; outcome for the user is the same (alerts and incidents not protected by customer keys). | PREP-GOV-03 |
| 7 | Unified RBAC status | No page labels unified RBAC for Sentinel as GA or preview. A third-party blog reports possible automatic enablement (MC1457836), unverified. | Decision item with an unverified-report caveat. | PREP-ACC-03 |
| 8 | Correlation default | The transition guide says the Defender XDR engine "fully controls" grouping; the correlation settings page (2026-10-04) says analytics rules are excluded by default at first onboarding, with a tenant toggle off by default. | Advises reading the actual tenant setting after connection; correlation decision is explicit. | PREP-DET-02, PREP-DET-05, TEST-05, TRN-14, VAL-05 |
| 9 | Description field | "SecurityIncident no longer includes a Description field", but the table schema reference still lists the column. | Interpreted as "not populated"; verify empirically. | PREP-INT-02 |
| 10 | alertProductNames / $expand | The transition guide mixes the Sentinel API (`additionalData.alertProductNames`) and Graph (`$expand=alerts`). Graph incidents have no `providerName` or `alertProductNames`. | Explains which field lives in which API. | PREP-INT-02 |
| 11 | Defender for Cloud opt-out | No current UI path documents opting out of Defender for Cloud incident sync. Both connectors are hidden in the Defender portal. | Older "opt-out" guidance flagged as possibly outdated; configure in the Azure portal. | PREP-CON-02 |
| 12 | Alert-only alerts after connection | Not stated where they can be queried (only incident-linked Sentinel alerts are in `AlertInfo`). | Inference (workspace `SecurityAlert`) marked as such. | PREP-DET-04 |
| 13 | Add/remove alerts | The same page says moving alerts between incidents is supported in the Defender portal, but adding or removing alerts is not supported (for playbooks). | Distinguishes the UI (supported) from playbooks and the API (not supported). | PREP-AUT-03 |
| 14 | NRT custom detections on Sentinel data | Advanced hunting known issues say unavailable; the newer custom detection page lists supported Sentinel tables. | Newer page preferred; flagged. | PREP-DET-08 |
| 15 | Test environment strategy | No official guidance on testing the transition in non-production first. Same-tenant test workspaces interact with primary selection and the Defender XDR connector. | Recommendation derived from documented behaviour and labelled as such. | PREP-PLN-04, TEST-01 |
| 16 | Offboarding reversal | Not documented whether Fusion, Microsoft incident creation rules, auto-disconnected connectors or app role assignments are restored on disconnect. | Backup before change; optional disconnection rehearsal in test. | PREP-PLN-01, PREP-PLN-03, TEST-10 |
| 17 | Table-level / resource-context RBAC beyond IdentityInfo | Behaviour in the Defender portal is undocumented. | Validate with restricted test users. | PREP-ACC-04 |
| 18 | Threat intelligence naming and licensing | Sentinel pages say "Intel management"; newer Defender pages say "Overview / Intel explorer". The transition guide still ties Intel Profiles/Explorer to MDTI customers, although MDTI reached end of life on 2026-08-01 with capabilities at no extra cost. | Both names shown; licensing statement taken from the end-of-life announcement. | PREP-CNT-05 |
| 19 | Data lake for existing customers | The September 2026 change ("evolves to data lake retention after Sentinel onboarding") is ambiguous for existing customers who connect later; there is a billing-meter switch. | Data lake treated as a separate decision; confirm before connecting if cost predictability matters. | PREP-GOV-04 |
| 20 | Repositories status | The transition guide says public preview; What's new (March 2026) says GA. | Check current status before relying on it. | PREP-TOP-06 |
| 21 | Azure-portal-only workarounds after 2027-03-31 | Adding entities to TI, manual playbook runs on alerts/entities, creating automation rules from an incident, and "Open in Azure" workbook visuals have no documented post-retirement path. | Treated as temporary; durable replacements required. | PREP-AUT-04, PREP-OPS-02, PREP-CNT-01, VAL-17 |
| 22 | Health table casing | `SentinelResourceType` values differ in casing between the reference and Microsoft's samples (`==` is case-sensitive). | Verbatim samples kept; caveat advises `=~`. | K_RULE_HEALTH, K_HEALTH_OVERVIEW |
| 23 | Stable API rule kinds | `2025-09-01` enumerates only Scheduled, MicrosoftSecurityIncidentCreation and Fusion; NRT and ML appear in `2025-07-01-preview`. | Inventory runs both versions and compares counts. | PREP-DET-01, inventory script |
